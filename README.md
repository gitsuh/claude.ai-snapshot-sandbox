# Claude Sandbox Snapshot

A single Bash script that saves and restores your entire working state inside **Claude.ai's ephemeral code sandbox**.

> Claude.ai runs your code in a temporary sandbox. When its container resets — after idle time, a long session, or routine maintenance — every file and installed package is wiped and **cannot be recovered afterward**. `snapshot.sh` packages the full working state into one portable `.tar.gz` so you can rebuild it in a fresh sandbox, whether in the same chat or a brand-new one.

---

## Why this exists

There are two layers of "context" in a Claude.ai session. The **conversation** — what you discussed and decided — persists in Claude.ai and survives a reset on its own. The **sandbox filesystem** — your files, installed packages, and in-memory state — does not, and once a container resets there is no way to reattach to it.

`snapshot.sh` captures that second layer (files + environment) plus a short written summary, bundles it into a single archive, and gives you a one-step way to rebuild everything later.

## What's in this repository

- **`snapshot.sh`** — the only script you need.
- **`README.md`** — this file.

Everything else you'll see referenced below — `restore.sh`, `STATE.md`, `README_RESTORE.txt`, and the `files/` and `meta/` folders — is **generated by `snapshot.sh` into each archive at runtime**. None of it lives in the repo; you don't add or maintain it yourself.

## What a snapshot contains

Running `snapshot.sh` produces a timestamped `.tar.gz` with this layout:

```
mywork_20260529T013917Z/
├── snapshot.sh            # a copy of the tool itself, so you can snapshot again
├── restore.sh             # generated: rebuilds files + reinstalls packages
├── README_RESTORE.txt     # generated: plain-English restore instructions
├── STATE.md               # generated: a fill-in project/context summary
├── files/                 # your working files, under their original paths
│   └── home/claude/...
└── meta/
    ├── requirements.txt   # pip freeze
    ├── npm-packages.json  # npm ls          (only if Node is present)
    ├── apt-manual.txt     # apt packages    (only if any were installed)
    ├── inventory.sha256   # checksums, used to verify the restore
    └── env-info.txt       # OS / Python / Node versions
```

Files are stored under their original absolute paths, and `node_modules`, `.git`, `__pycache__`, and `*.pyc` are skipped to keep archives small.

## Requirements

- Runs inside Claude.ai's code sandbox (or any Linux/macOS shell).
- Standard tools only — `bash`, `tar`, `find`, `sha256sum`, `pip`. No installation, no dependencies.
- For **restoring**, turn **network access ON** in the chat's settings so packages can be reinstalled.

## Usage

### Save your work (in a Claude.ai chat)

1. Upload `snapshot.sh` to the chat where you've been working.
2. Ask Claude:
   > Run the snapshot.sh I uploaded to save my work. If my files aren't in the default directory, set `SNAPSHOT_DIRS` to the right path first, then give me the `.tar.gz` to download.
3. Download the resulting `.tar.gz` and keep it somewhere safe.

### Restore later (a new chat, or after a reset)

1. Turn **network access ON** in the chat's Settings.
2. Upload your snapshot `.tar.gz` — it already contains `restore.sh`.
3. Ask Claude:
   > I uploaded a snapshot `.tar.gz` made by snapshot.sh. Run `restore.sh` on it to rebuild my files and reinstall packages, then read `STATE.md` and tell me where we left off.

### Options

| | |
|---|---|
| `bash snapshot.sh [label]` | `label` prefixes the archive name (default: `snapshot`) |
| `SNAPSHOT_DIRS="..."` | space-separated dirs/files to capture (default: current directory) |
| `OUT_DIR="..."` | where to write the archive (default: `/mnt/user-data/outputs` if it exists, else the current directory) |

Example:

```bash
SNAPSHOT_DIRS="/home/claude/project /home/claude/notes.md" bash snapshot.sh myproject
```

### Command line (outside Claude)

The same scripts work in any terminal:

```bash
bash snapshot.sh myproject              # -> ./myproject_<timestamp>.tar.gz

# later, in a fresh environment:
tar -xzf myproject_<timestamp>.tar.gz
cd myproject_<timestamp>
bash restore.sh                         # restore to the original paths
# or restore under a different folder:
bash restore.sh "" /path/to/restore/here
# or point restore.sh straight at the archive, without extracting first:
bash restore.sh myproject_<timestamp>.tar.gz
```

## How restore works

The generated `restore.sh` extracts your files back to their original paths, reinstalls the Python packages from `requirements.txt` (this is the step that needs network access), verifies every restored file against the `sha256` inventory, and then points you to `STATE.md`.

## Keeping context across chats — `STATE.md`

A reset doesn't erase the conversation, but a **brand-new chat** has no memory of the work. `STATE.md` is a short, fill-in summary — goal, current status, key files, decisions that must not be re-guessed, and the next step — that travels inside the archive so a fresh Claude can pick up cleanly. Edit it as you work and re-run `snapshot.sh` to bake the latest version in. If a `STATE.md` already exists among your captured files, `snapshot.sh` keeps yours instead of overwriting it.

## FAQ

**When does the container reset?**
Anthropic doesn't publish a fixed time, and it isn't a single number — the container recycles on the first of several triggers. Inactivity (idle eviction) is the most common, alongside a cap on how long a single container can be used, per-operation time limits, running out of memory/disk, and backend maintenance. Assume it can happen at any session boundary, and sometimes mid-session.

**Can I recover a container after it resets?**
No. The old container is gone and there's no way to reattach to it. That's the whole reason to snapshot beforehand and rebuild from the archive.

**Does a reset delete my chat?**
No — the conversation persists in Claude.ai. Only the sandbox filesystem is wiped.

**Restore didn't reinstall my packages.**
Make sure network access is enabled for that chat. Without it, your files still restore, but `pip` can't reach the package index.
